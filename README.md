# Team Chat Backend

Laravel API and real-time server for the WhistleIt team chat web app. It uses MongoDB for data and serves the frontend team through a versioned REST API under `/api/v1`.

## Requirements

- PHP (the version your Laravel release requires) and Composer
- The PHP `mongodb` extension. Check with `php -m | grep mongodb`
- MongoDB running locally on `localhost:27017`
- Git

## First-time setup

```bash
git clone git@github.com:team-backend-dev/team-chat-backend.git
cd team-chat-backend
composer install
cp .env.example .env
php artisan key:generate
```

Then open `.env` and check these values:

```dotenv
DB_CONNECTION=mongodb
MONGODB_URI=mongodb://localhost:27017
MONGODB_DATABASE=team_chat
SESSION_DRIVER=file
QUEUE_CONNECTION=sync
CACHE_STORE=file
FRONTEND_URL=http://localhost:3000
```

Run `php artisan config:clear` after any `.env` change.

For local development mail delivery, leave the default mailer as `log` unless you explicitly configure SMTP or another provider.

## Company-scoped team API

This backend is intentionally team-only. Company and invitation routes are removed, and team access is scoped by the authenticated user's company instead of a company selector.

### Active API surface

Authenticated routes under `/api/v1`:

- `GET /api/v1/teams`
- `POST /api/v1/teams`
- `GET /api/v1/teams/{team}`
- `PUT /api/v1/teams/{team}`
- `PATCH /api/v1/teams/{team}`
- `DELETE /api/v1/teams/{team}`
- `GET /api/v1/teams/{team}/members`
- `POST /api/v1/teams/{team}/members`
- `DELETE /api/v1/teams/{team}/members/{user}`

The server resolves the current company from the authenticated user and authorizes team access from that company context. No comapny route or comapny ID is expected in the request.

## Team endpoints

### Team collection

| Method | URL | Auth required | Purpose |
| --- | --- | --- | --- |
| `GET` | `/api/v1/teams` | Yes | List teams for the current company |
| `POST` | `/api/v1/teams` | Yes | Create a team |
| `GET` | `/api/v1/teams/{team}` | Yes | Fetch one team |
| `PUT` / `PATCH` | `/api/v1/teams/{team}` | Yes | Update a team |
| `DELETE` | `/api/v1/teams/{team}` | Yes | Delete a team |

Create team request body:

```json
{
  "name": "Product"
}
```

### Team membership endpoints

| Method | URL | Auth required | Purpose |
| --- | --- | --- | --- |
| `GET` | `/api/v1/teams/{team}/members` | Yes | List team members |
| `POST` | `/api/v1/teams/{team}/members` | Yes | Add a member to a team |
| `DELETE` | `/api/v1/teams/{team}/members/{user}` | Yes | Remove a team member |

Add team member request body:

```json
{
  "user_id": "user_789",
  "role": "member"
}
```

## Development setup

The default app seeder is intentionally empty because the team-only backend does not create comapny demo data. For local development, seed only the company and team data needed for the current product flow.

## Required environment variables

The backend expects these values in a local `.env` file without exposing actual secrets or staging credentials:

```dotenv
APP_ENV=local
APP_KEY=replace-with-your-local-key
APP_URL=http://localhost

DB_CONNECTION=mongodb
MONGODB_URI=mongodb://localhost:27017
MONGODB_DATABASE=team_chat

SESSION_DRIVER=file
CACHE_STORE=file
QUEUE_CONNECTION=sync
MAIL_MAILER=log
FRONTEND_URL=http://localhost:3000
```

Do not commit `.env` values, Atlas connection strings, or production credentials. Treat any environment values as local-only configuration.

## Authentication

All authenticated endpoints require the custom token header used by the app:

```http
AuthorizationKey: <plain-text-token>
```

The token value is generated by the server and stored as a SHA-256 hash in `user_tokens`. The app reads and verifies the token in the `AuthToken` middleware and returns `401` for missing or invalid tokens.

## Database rules

- **Daily development:** every member uses their own local MongoDB, database name `team_chat`. Never share one local database between people.
- **Staging:** a shared MongoDB Atlas database (`team_chat_staging`) is used by the staging server that the frontend team calls. The lead manages it.
- **Switching:** you can keep the Atlas line in your own `.env` as a comment and uncomment it when needed. Only one `MONGODB_URI` should be active at a time.
- **Never commit** `.env`, an Atlas connection string, or a password. `.env.example` holds safe defaults only.
- MongoDB creates collections on first insert. Migrations are used for **indexes**.
- After pulling new code, run:

```bash
php artisan migrate
php artisan db:seed
```

## Project conventions

- Every model extends `MongoDB\Laravel\Eloquent\Model`. The `User` model extends `MongoDB\Laravel\Auth\User`.
- All routes live under `/api/v1`.
- Controllers stay thin. Use Form Requests for validation, API Resources for responses, and Services or Actions for business logic.
- Use one error format and cursor pagination (`?before=<id>`) across all endpoints.
- Every endpoint is covered by a policy check.
- Any change to the API contract is announced to the frontend team before it is deployed.

## Git workflow

- Branches: `main` (stable releases) and `develop` (integration). Nobody pushes directly to either.
- Start every task from an updated `develop`:

```bash
git checkout develop
git pull origin develop
git checkout -b feature/<your-name>/<task>
```

- Push only to your own branch, then open a pull request into `develop`.
- Every pull request needs a review from the team lead before it is merged.
- Keep pull requests small, and include the migration, tests and API collection entry for your endpoint.
- Keep your branch up to date with:

```bash
git fetch origin
git merge origin/develop
```

## Troubleshooting

| Problem | Likely cause |
| --- | --- |
| `Database connection [mongodb] not configured` | The `mongodb` connection is missing in `config/database.php`, or the config cache is stale. Run `php artisan config:clear` |
| `Class MongoDB\Driver\Manager not found` | The PHP `mongodb` extension is not loaded for this PHP version |
| Errors about missing `sessions`, `cache` or `jobs` tables | `SESSION_DRIVER`, `CACHE_STORE` or `QUEUE_CONNECTION` is still set to `database` in `.env` |
| Connection timeout | MongoDB is not running on `localhost:27017` |
| Frontend requests blocked | `FRONTEND_URL` is missing or does not match the frontend address |
